## 1. المشكلة

- **لا فريق أمني:** المنشأة الصغيرة لا تملك محللًا يراقب على مدار الساعة، ولا ميزانية لمركز عمليات أمنية.
- **الهجوم متعدد المراحل:** المهاجم يفحص منافذ الخادم، ثم يبحث في الموقع عن ملف مكشوف، ثم يحاول الدخول.
- **أدوات متفرقة:** كل أداة ترى جزءًا من الصورة وتطلق تنبيهاتها وحدها، فيضيع الربط ويتأخر القرار.

## 2. الحل في مسار واحد

```
مصادر المنشأة ← الكشف (نماذج + قواعد) ← فريق الوكلاء ← قرار صاحب المنشأة ← التنفيذ على خادمه
```

مبدآن لا يُكسران:
1. **لا شيء يُنفَّذ دون موافقة صاحب المنشأة.**
2. **كل منشأة معزولة تمامًا عن غيرها.**

## 3. المنصة: ستة أجزاء

| الجزء | ما يفعله |
|---|---|
| **1. النواة متعددة المنشآت** | تسجيل ذاتي، ومفتاحان بصلاحيات منفصلة (استقبال للإرسال فقط، ولوحة للقرار)، وقاعدة SQLite مستقلة لكل منشأة، ولا يُخزَّن أي مفتاح خام |
| **2. السجلات** | استقبال سجلات Nginx وApache والجدار الناري (iptables/UFW). قواعد للتخمين وفحص المسارات والحقن والإغراق وفحص المنافذ، ونموذج شذوذ يتعلّم سلوك زوّار المنشأة نفسها |
| **3. التنبيهات والموافقة** | Webhook موقّع بـ HMAC وTelegram. رابط موافقة لكل مقترح: لمرة واحدة، صالح ساعة، يفتح صفحة تأكيد ولا ينفّذ بمجرد الفتح. منفّذ مرجعي على خادم المنشأة يطبّق `ufw`، وله وضع تجربة |
| **4. المراقبة الخارجية** | التوفر، والشهادة، وترويسات الأمان، والملفات الحساسة المكشوفة. درجة من A إلى F، وإصلاح جاهز للنسخ لـ Nginx وApache. لا يبدأ الفحص العميق إلا بعد إثبات الملكية بملف أو بسجل DNS |
| **5. وكيل الخادم** | وكيل خفيف يلخّص كل اتصال إلى 77 خاصية (نفس خصائص التدريب)، ولا يرسل محتوى الحزم أبدًا. يعمل بصلاحية `CAP_NET_RAW` بدل root، ومخزنه المحلي 24 ساعة يعيد الإرسال عند الانقطاع |
| **6. المنسّق متعدد الوكلاء** | يربط حوادث المصادر المختلفة في «حملة» بقواعد قابلة للتفسير، ويكتب تقريرًا واحدًا بمراحل الهجوم، وقرارًا واحدًا لكل مهاجم |

## 4. طبقة الكشف والتنبؤ

| النموذج | المهمة | النتيجة |
|---|---|---|
| Random Forest ثنائي | هجوم أم طبيعي | يرصد **94.8%** من الهجمات |
| Random Forest بسبع فئات | نوع الهجوم | Macro-F1 = **95.2%** |
| مجموعة من 5 نماذج LSTM | بداية الهجوم في الدقيقة التالية | ترصد **41%** من البدايات مسبقًا، والصدفة قرابة 18% |

- **التدريب:** قرابة 2.83 مليون اتصال من CICIDS2017، بتقسيم زمني صارم: النموذج لم يرَ بيانات الاختبار.
- **حاجز الأدلة:** النموذج لا يفتح حادثة إلا بـ 20 اتصالًا على الأقل، وثقة 80%، ونسبة هجوم 50%.
- **مؤشر LSTM للإنذار المبكر فقط**، ولا يفتح حادثة وحده.
- **الكاشف السلوكي** يعمل بجانب النموذج: فحص، ومسح، وتخمين، وإغراق، وDDoS. وقاعدة DDoS في المنصة تشترط 1000 اتصال على الأقل، و5 أضعاف المعتاد، حتى لا يكفي خادم مزدحم وحده لإطلاقها.

## 5. فريق الوكلاء

**المتخصصون:**
- **محلل السجلات:** يحقق في حوادث السجلات. أدواته: النظرة العامة، ونشاط العنوان، وعيّنة الطلبات، وسياق الشذوذ، والسياسة، والمقترح.
- **محلل الشبكة:** يحقق في حوادث وكيل الخادم. أدواته: المصادر المشبوهة، وتفسير قرار النموذج، والتنبؤ، والسياسة، والمقترح.

**المنسّق:** إذا ارتبطت الحوادث في حملة، يقرأ تقارير المتخصصين. ثم يبني ملف كل مهاجم عبر المصادر، ويفحص الحد الأقصى المسموح، ويكتب تقريرًا بمراحل: ثغرة مكشوفة ← استطلاع ← محاولة دخول ← استغلال أو تسريب ← تعطيل.

**قاعدتا الربط** (كل ربط له سبب مكتوب يراه صاحب المنشأة):
1. **نفس المهاجم:** نفس العنوان في حادثتي سجلات أو شبكة خلال 24 ساعة. القائمة البيضاء لا تربط شيئًا.
2. **الملف المكشوف:** مهاجم طلب مسارًا كشفته المراقبة. الرد 200 يعني تسريبًا فعليًا، فترتفع الحملة إلى «حرجة».

**القرار الموحّد:**
- مقترحات المتخصصين المعلّقة لنفس العنوان تصبح «دُمج في الحملة»، فتبطل روابط موافقتها القديمة.
- موافقة واحدة على الحملة تُنفَّذ مرة واحدة وتغلق الحوادث الأعضاء. حوادث المراقبة تبقى مفتوحة حتى يُصلح الموقع.

**التقنية:**
- الوكلاء مبنيون على Claude باستدعاء الأدوات (Tool Use): كل أداة تستدعي طبقة حقيقية من النظام، والوكيل لا ينفّذ شيئًا بنفسه.
- **بلا مفتاح API** يعمل «وضع العرض»: نفس الأدوات الحقيقية بخطوات ثابتة، والتقرير من قوالب. الواجهة تعلن هذا الوضع صراحة.
- **عند فشل الوكيل** يعمل بديل القواعد الثابتة تلقائيًا.

## 6. الحواجز والأمان

- **لا إجراء أشد مما تسمح به السياسة، ولا حظر لعنوان في القائمة البيضاء.** يُعاد فحص الحاجز عند التنفيذ أيضًا.
- **الحجم:** حد لعدد القواعد النشطة، وحد لعدد الدفعات في الدقيقة، وحد لحجم الدفعة وفك الضغط.
- **حماية من SSRF:** عبر `ALLOW_PRIVATE_WEBHOOKS=false` و`ALLOW_PRIVATE_TARGETS=false` في أي نشر حقيقي.
- **سجل تدقيق كامل:** كل تحقيق وقرار ونتيجة تنفيذ محفوظة في `agent_runs/` لكل منشأة.
- **العزل:** المنشأة تُستنتج من المفتاح فقط، وحادثة منشأة أخرى ترجع 404 حتى لا يُكشف وجودها.

## 7. النتائج المقيسة

كل التقييمات قابلة للإعادة، ولا تستهلك رصيد API.

| التقييم | النتيجة | الملف |
|---|---|---|
| الكشف الشبكي: 6 أنواع × حجمان × 5 بذور | رُصد كل مهاجم، ونوع النموذج صحيح 100%، و**0 تنبيه** خلال 300 دقيقة طبيعية | [network_detection.md](../docs/results/network_detection.md) |
| كشف السجلات: 6 أنماط × 5 بذور | 100% بالكاشف المقصود، و0 تنبيه كاذب | [log_detection.md](../docs/results/log_detection.md) |
| ربط الحملات: 10 سيناريوهات فيها طُعوم | الدقة والاسترجاع 100%، ولا طُعم مربوط، والموافقات لكل مهاجم 3 ← 1 | [campaign_linking.md](../docs/results/campaign_linking.md) |
| الاختبارات الآلية | **229 اختبارًا تنجح** | `tests/` |

**لماذا التعلّم الآلي؟** عند هجوم هادئ (25 اتصالًا في الدقيقة) لم تلتقط القواعد السلوكية DoS وDDoS والويب والبوتنت، والتقطها النموذج كلها وحدد نوعها.

```bash
python -m netdetect.evaluate      # الكشف الشبكي
python -m ingest.evaluate         # كشف السجلات
python -m campaign.evaluate       # ربط الحملات
python -m pytest tests -q         # الاختبارات
```

## 8. التشغيل

```bash
python3 -m venv project && source project/bin/activate
pip install fastapi uvicorn scikit-learn tensorflow scapy pandas numpy joblib anthropic python-dotenv pytest
python train_baseline_model.py && python train_attack_type_model.py && python train_final_lstm.py

```

ثم افتح `http://localhost:8001/app/`. لتشغيل Claude بدل وضع العرض: انسخ `.env.example` إلى `.env` وضع `ANTHROPIC_API_KEY`، ثم أعد تشغيل الخادم.

### عرض حي أمام اللجنة (منشأة ديمو جاهزة)

1. **موقع الديمو بملف `.env` مكشوف:**
   ```bash
   python demo_site.py --port 8091
   ```
2. **منشأة «متجر التمور» كاملة.** يومان من السجلات، ووكيل خادم متصل، ومراقبة الموقع، ثم حملة تنتظر قرارك:
   ```bash
   python demo_video/seed_demo.py --keepalive
   ```
3. **المنفّذ في وضع التجربة،** بالسرّ الموجود في `demo_video/out/demo_keys.json`:
   ```bash
   PC_WEBHOOK_SECRET=<السر> python enforcer/receiver.py --port 9000
   ```
4. افتح اللوحة وادخل بـ `dashboard_key` من نفس الملف.

**مسار العرض المقترح:**
1. «منشأتي»: المصادر المتصلة.
2. «نظرة عامة»: أرقام النماذج.
3. «المراقبة»: الدرجة F والملف المكشوف والإصلاح.
4. «منشأتي»: الحملة وأعضاؤها.
5. افتح الحملة: سلسلة المراحل، و«لماذا رُبطت؟»، وتقرير المنسّق.
6. «وافق»: يظهر رد المنفّذ وتُغلق الحوادث.

## 10. حدود معلنة

- **مصدر الأرقام:** التقييم على إعادة تشغيل CICIDS2017 وبيانات مولّدة، لا على ترافيك منشأة حقيقية بعد.
- **خصائص ناقصة:** خصائص Bulk وActive/Idle مصفّرة في وكيل الخادم، لأنها تتطلب CICFlowMeter الكامل.
- **مؤشر LSTM** إنذار مبكر فقط.
- **السجلات لا تحدد الموقع المطلوب،** فقاعدة الملف المكشوف تطابق المسار على مستوى المنشأة.
- **الحوادث المجمّعة:** الحوادث من نفس النوع خلال 30 دقيقة تُجمع في حادثة واحدة، فقد تضم عناوين أخرى بجانب المهاجم. المنسّق يقرر لكل عنوان على حدة.
- **أُعدّ للعرض لا للنشر:** النموذج الأولي معدّ للمسابقة، لا لنشر إنتاجي.

## 11. الخطوة التالية

- تجربة ميدانية على منشأة صغيرة حقيقية.
- تقرير أمني دوري لصاحب المنشأة.

## 12. أسئلة متوقعة من اللجنة

**هل يمكن أن يحظر النظام عميلًا بريئًا؟**
لا يُنفَّذ أي شيء دون موافقة صاحب المنشأة، والقائمة البيضاء لا تُحظر أبدًا، والنموذج لا يفتح حادثة إلا بعد حاجز الأدلة. في التقييم: صفر تنبيهات على عناوين بريئة.

**هل تخرج بيانات المنشأة؟**
وكيل الخادم يرسل ملخصات اتصالات (أرقامًا) لا محتوى الحزم. وبيانات كل منشأة في قاعدة مستقلة.

**ما دور الذكاء الاصطناعي تحديدًا؟**
1. نماذج الكشف تلتقط الهجمات الهادئة التي تفوت القواعد.
2. النموذج يحدد نوع الهجوم.
3. LSTM ينذر مبكرًا.
4. فريق الوكلاء يحقق ويربط ويشرح بلغة يفهمها صاحب المنشأة.

**ماذا لو لم يتوفر مفتاح Claude أو تعطّل؟**
وضع العرض يعمل بنفس الأدوات الحقيقية، وبديل القواعد الثابتة يعمل عند أي فشل، فلا تتوقف الحماية.

**كم يكلّف التشغيل؟**
الحوادث غير المرتبطة لا تكلّف إلا تحقيق متخصص واحد. والمنسّق نداء واحد لكل حملة. والتقييمات كلها بلا تكلفة API.
