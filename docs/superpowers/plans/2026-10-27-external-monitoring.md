# خطة تنفيذ: المراقبة الخارجية للموقع (الجزء 4)

> طلب صاحب المشروع التنفيذ مباشرة بعد الخطة، فهي تحدد الملفات والواجهات وحالات الاختبار، والكود يُكتب بالاختبار أولًا مع commit لكل مهمة.

- **مستند التصميم:** [2026-10-27-external-monitoring-design.md](../specs/2026-10-27-external-monitoring-design.md)
- **الفرع:** `platform-core`

## قرارات تقنية

- **حزمة `monitor/` مستقلة** بموجّه خاص (`/api/v1/monitor`) حتى لا يتضخم `tenancy/api.py`.
- **الجلب بـ urllib** مع معالج تحويل يتحقق من العنوان الداخلي في كل تحويل ويحد العدد بـ 5، ومحلل أسماء قابل للاستبدال في الاختبارات.
- **فصل الحوادث بالنوع:** عمود `kind` (`log` أو `monitor`) في جدول `incidents`؛ التجميع خلال 30 دقيقة يتم داخل النوع نفسه فقط، حتى لا تُلحق حادثة تعطّل بحادثة هجوم. قواعد البيانات القائمة تُرقّى بـ `ALTER TABLE` عند الفتح. حادثة المراقبة لا تدخل طابور المحلل، و«حقّق» عليها يرجع 422.
- **`dnspython` اختياري:** إن لم يكن مثبتًا، التحقق بـ DNS يرجع «غير متاح» والملف يعمل.
- **الاختبارات تستخدم خادم HTTP حقيقيًا محليًا** (`http.server` في خيط) بسلوك قابل للضبط لكل اختبار، ومحلل DNS وهمي.

## خريطة الملفات

| الملف | المسؤولية |
|---|---|
| `monitor/fetch.py` | `fetch(url, allow_private, resolver)` ← `Response(status, headers, cookies, body, ms, error)`؛ `is_private_host` |
| `monitor/checks.py` | كتالوج الملاحظات بالعربية وإصلاحاتها؛ `availability`، `header_findings`، `exposed_files`، `score` |
| `monitor/store.py` | `SiteStore(tenant.db)`: المواقع، الفحوص (7 أيام)، الملاحظات (فتح/حل)، التوفر 24 ساعة |
| `monitor/verify.py` | `verify_file`، `verify_dns` |
| `monitor/service.py` | `Monitor`: `add_site`، `verify`، `run_site` (التوفر والانتقالات والفحص العميق والحوادث والتنبيهات)، `summary`، المجدول |
| `monitor/api.py` | `GET/POST /sites`، `DELETE /sites/{id}`، `POST /sites/{id}/verify`، `POST /sites/{id}/check` |
| `ingest/store.py` | عمود `kind` وتجميع داخل النوع |
| `tenancy/api.py` | `Platform.monitor` و`allow_private_targets`؛ رفض «حقّق» لحوادث المراقبة؛ `kind` في قائمة الحوادث |
| `notify/channels.py` و`enforcer/receiver.py` | نص `monitor.alert`؛ المنفّذ يقبله بـ `ignored` |
| `demo_site.py` | موقع العرض بثغرات مقصودة و`/__down` و`/__fix` |
| `api_server.py` و`web/*` | التركيب والمجدول؛ صفحة «المراقبة»؛ حوادث المراقبة تنقل إليها |

## المهام

1. **الجلب والفحوص والدرجة** (`tests/test_monitor_checks.py`): موقع بلا ترويسات ← الملاحظات والدرجة المتوقعة؛ موقع مكتمل ← A؛ HSTS لا يُطلب في HTTP؛ إصدار `Server` يُكشف وغير المرقّم لا؛ ملفات تعريف بلا HttpOnly؛ SPA يرد 200 لكل شيء ← لا ملفات مكشوفة؛ `.env` و`.git/HEAD` حقيقيان ← critical؛ عنوان داخلي مرفوض عند المنع، وتحويل إلى عنوان داخلي مرفوض؛ مهلة/رفض اتصال ← «متعطل».
2. **التخزين والتحقق والخدمة** (`tests/test_monitor_service.py`): التحقق بالملف وبـ DNS وهمي ورمز خاطئ؛ لا فحص عميق قبل التحقق؛ تعطلان ← حادثة `site_down` و`monitor.alert`، والعودة تغلقها وتنبّه؛ ملف مكشوف ← حادثة `exposed_file` وتُغلق عند الإصلاح؛ حادثة المراقبة لا تُلحق بحادثة سجلات قريبة؛ حد 5 مواقع؛ حد «افحص الآن»؛ التوفر 24 ساعة.
3. **الـ API والتكامل** (`tests/test_monitor_api.py`): إضافة وعرض وحذف؛ عزل المنشآت (404)؛ عنوان داخلي 422 عند المنع؛ 429 لـ «افحص الآن»؛ «حقّق» على حادثة مراقبة 422؛ المنفّذ يقبل `monitor.alert` بـ `ignored`؛ نص Telegram لـ `monitor.alert`.
4. **موقع العرض والواجهة والتوثيق:** `demo_site.py`؛ صفحة «المراقبة»؛ README. تحقق: موقع العرض ← إضافة وتحقق ← درجة F بملاحظات و`.env` مكشوف ← `/__fix` ← درجة أفضل وإغلاق الحادثة ← `/__down` ← حادثة تعطّل ← العودة تغلقها.
